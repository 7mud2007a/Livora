# LIVORA — website

Premium furniture and interior design. A single-page, bilingual (English / Arabic, LTR / RTL) website built with
**React, Three.js and GSAP**, with a scroll-driven 3D "About" story that uses the supplied chair model.

Everything runs on your own machine or any static host. There is no server code, no repository and no
deployment step in this project: `npm run build` produces a folder of static files (`dist/`) and that is all.

---

## 1. Quick start

You need **Node.js 18.18 or newer** (https://nodejs.org) and an internet connection for the one-time install.

```bash
cd LIVORA-WEBSITE
npm install          # installs React, Three.js, GSAP and esbuild
npm run dev          # development server with live reload → http://localhost:5173
npm run build        # production build → dist/
npm run preview      # serves dist/ locally → http://localhost:4173
```

A ready-made production build is already included in `dist/` (open it through any static web server; opening
`index.html` straight from the disk will not work because the 3D model and fonts are loaded by URL).

| Script            | What it does                                                                       |
| ----------------- | ---------------------------------------------------------------------------------- |
| `npm run dev`     | esbuild in watch mode + a static server with automatic reload (`PORT=…` to change). |
| `npm run build`   | Bundles, minifies, content-hashes and writes `dist/` (including everything in `public/`). |
| `npm run preview` | Serves `dist/` with sensible cache headers (`PORT=…` to change).                    |

> **About the build tool.** The project uses **esbuild** with three small scripts in `scripts/` instead of Vite
> (the package registry was not reachable while the project was assembled, so the toolchain was kept to a single
> dependency). Nothing in `src/` is esbuild-specific: if you prefer Vite, `src/main.jsx` is a normal entry point and
> `public/` is a normal public folder; the main change is renaming `import.meta.env.PUBLIC_*` to `import.meta.env.VITE_*`
> in `src/config/site.js`.

### Environment variables

Copy `.env.example` to `.env` (or `.env.local`) **before** building. Only variables that start with `PUBLIC_` reach the
browser.

| Variable                  | Purpose                                                                                                     |
| ------------------------- | ----------------------------------------------------------------------------------------------------------- |
| `PUBLIC_SITE_URL`         | The site's public address, e.g. `https://www.example.com` (no trailing slash). Used for the absolute Open Graph image URL and the canonical link. |
| `PUBLIC_CONTACT_ENDPOINT` | Where the contact form sends its message (see section 5). Leave empty until you have one.                   |

---

### If something goes wrong

* `npm install` fails → check `node -v` (18.18 or newer) and that your network allows the npm registry.
* Blank page when opening `dist/index.html` by double-click → use `npm run preview` (or any web server).
* The 3D story does not appear → your browser has WebGL turned off or the model failed to load; the page then shows the
  readable static version of the same story (this is intentional).

| You want to change…                    | Edit                                                                                 |

### Products

`src/data/products.js` exports `PRODUCTS`. Every entry is currently a clearly labelled **placeholder**
(`placeholder: true`: a tag on the card, "0,000" prices, "to be confirmed" dimensions) — no stock, price or
specification is invented. To add a real product, copy an entry and set:

```js
{
  id: 'my-armchair',                 // also the image file prefix
  category: 'seating',               // seating | tables | lighting | storage (see CATEGORIES; labels in content/*.js)
  placeholder: false,                // removes the placeholder tag and note
  name: { en: '…', ar: '…' }, variant: { en: '…', ar: '…' }, description: { en: '…', ar: '…' },
  specs: [{ label: { en: 'Width', ar: 'العرض' }, value: { en: '82 cm', ar: '٨٢ سم' } }],
  price: { amount: 1450, currency: 'USD' },   // amount: null → "price to be confirmed"
  image: { alt: { en: '…', ar: '…' } },
}
```

and add `public/images/products/my-armchair-640.webp` (640 px wide) and `…-1000.webp` (1000 px wide), both **4:5 portrait**.
`ProductCard` and `ProductDialog` only depend on this shape, so the data can also come from a CMS or an API later.

### Images

The pictures supplied with this project are **renders** made from your chair model plus a simple procedural room — they

## 4. The About story (the signature section)

A pinned stage (`position: sticky`) inside a tall section. GSAP **ScrollTrigger** scrubs one timeline; the timeline
only writes numbers into a plain state object, and a **Three.js** render loop reads them — React never re-renders while
you scroll.

* **Five chapters.** The text alternates sides (right, left, right, left, right); the chair always takes the other half,
  and travels across between chapters without ever overlapping the words. Each chapter turns the chair a little.
* **Orientation.** `clock` in `src/components/about/storyConfig.js` is read as a position on a clock face seen from
  above, with the viewer at 6 o'clock: `5` turns the chair toward screen-right, `7` toward screen-left (`(6 − hour) × 30°`).
  Current values: 5 · 7 · 4.5 · 7.5 · 5.
* **Always alive.** Gentle float, a slow pendulum sway, continuous yaw drift, a lean that follows scroll speed (a sideways
  trail on desktop, a forward / backward rock on phones, where a sideways swing would leave the narrow screen), and a
  small pointer tilt on devices that have a pointer.
* **Everything tunable is in `storyConfig.js`**: scroll length per unit (`unitVh`), line pacing, hold time, crossing time,
  text sides, orientations, chapter backgrounds (official palette colours), shadow strength.
* **Right-to-left.** With `mirrorInRtl: true` the sides (and the chair's turns) are mirrored in Arabic, so the text still
  sits in the reading-start half. Set it to `false` to keep the same sides in both languages.
* **Loading.** The Three.js code (a separate ~160 kB gzip chunk) and the 1.7 MB model are fetched only when the story is
  within about two and a half screens. Rendering pauses while the story is off-screen or the tab is hidden, and the pixel
  ratio adapts to keep frames smooth.
* **Phones and tall windows** get a redesigned layout: text and chair are stacked (chair above or below the words), and
  sentences appear one at a time. A phone held sideways, or any window shorter than 560 px, keeps the side-by-side layout
  and also shows one sentence at a time. The rule is the `useMedia` line at the top of `ScrollStory` in `AboutStory.jsx`.
* **Fallbacks.** With *reduced motion* (an opt-in "Play the animated story" button is offered), without WebGL, or if the 3D
  context is lost, the same five chapters appear as a readable static page with pre-rendered poses of the chair.

### The reserved scroll area

Directly under the hero there is an independent, deliberately empty block (`src/components/ReservedScroll.jsx`,
`src/styles/reserved.css`) kept for the custom scroll experience you will add. It is not coupled to anything else:

* length: `--reserved-height` in `reserved.css` (default `300vh`);
* a sticky stage exactly one viewport tall (`.reserved__stage`) — render your own content inside it;
* while it scrolls, `--reserved-progress` (0 → 1) is set on the section and a `livora:reserved-progress` event
  (`{ progress, element }`) is dispatched on `window`.

Delete the placeholder label (and the `aria-hidden`) when you add real content.

## 5. Contact form — what is needed to make it send

The form is complete on the front end: required-field and e-mail validation, error messages linked to their fields,
sending / success / error states, a hidden spam trap, and the same behaviour in both languages.

**It cannot deliver mail by itself — a website with no server has nowhere to send it.** Until you connect an endpoint, a
valid submission shows an honest notice ("this form is not connected to an email service yet, so nothing was sent") rather
than pretending to succeed.

To connect it, set `PUBLIC_CONTACT_ENDPOINT` to an HTTPS URL that accepts a JSON `POST` and rebuild:

```json
{ "name": "…", "email": "…", "subject": "…", "message": "…", "language": "en" }
```

Any form service that accepts JSON (Formspree-style), or a small serverless function of your own that sends the e-mail,
works. The endpoint must allow cross-origin requests (CORS) from your site's address. A successful response (any 2xx)
shows the success message; anything else shows the error message and keeps what the visitor typed.

## 6. Languages and direction

* `html[lang]` and `html[dir]` are set by a tiny inline script **before the first paint** (`?lang=ar|en` in the address →
  saved choice → browser language), so there is no flash of the wrong direction.
* Switching language **never reloads the page**: the layout is flipped, the section you were reading stays on screen
  (the scroll position is re-anchored to the same part of the same section), the choice is saved in `localStorage`
  (`livora:lang`), and `<title>`, description and Open Graph tags follow.
* All spacing and alignment use CSS logical properties, so RTL is a real mirror, not a patch. Arrows and transform origins
  use one `--flip` variable. In Arabic, numerals are shown as Arabic-Indic digits, letter-spacing and upper-casing are turned
  off (they would break the joins), and sizes and line heights are tuned for the Arabic face.
* The wordmark stays **LIVORA** in Latin letters in both languages.

## 7. Fonts — please read

The font you supplied is a single-weight **Arabic** face (it looks like *SF Arabic Black*). Two things follow from that:

1. **It contains Arabic glyphs only** — no Latin letters or digits, and no comma, semicolon, hyphen or dash. So it is
   used for everything Arabic (declared with `@font-face` in `src/styles/fonts.css`, with a `unicode-range` that gives it
   exactly the glyphs it has), and a companion Latin face fills the rest: **Inter / Inter Display** (SIL Open Font
   License — `public/fonts/LICENSE-Inter-OFL.txt`). Latin headings use Inter Display Light, text uses Inter. To use a
   different Latin face, edit `src/styles/fonts.css` and the `--f-sans` / `--f-display` variables in `tokens.css`.
2. **Licence.** If this is Apple's SF Arabic, Apple's font licence does not generally allow it to be embedded in a public
   website. Please confirm you have the rights to serve it on the web before launch; if not, swap the file in `fonts.css`
   for a web-licensed Arabic face — nothing else needs to change. The file is provided as `SFArabic-Black.ttf` (as supplied)
   and `SFArabic-Black.woff` (same font data in a web wrapper; converting to WOFF2 would shrink it further).

## 8. Accessibility, SEO and performance

* Semantic landmarks (`header`, `nav`, `main`, `section`, `footer`), one `h1`, a skip link, visible focus rings, `aria-current`
  on the active navigation item, `aria-pressed` on the language and filter buttons.
* The mobile menu and the product dialog trap focus, close with Esc, lock background scrolling and return focus. The
  dialog is the native `<dialog>` element.
* Touch targets are at least ~44 px (invisible hit areas on small text links), form fields use ≥ 16 px text (no zoom on iOS).
* Colour contrast follows WCAG AA for text. Secondary text on Warm Ivory uses **Deep Walnut**, because the Muted Brown
  Grey is 4.1 : 1 on that background; the Muted Brown Grey is used on Soft Cream, where it reaches 4.6 : 1.
* `prefers-reduced-motion` is respected everywhere (entrance animations, parallax, the 3D story, smooth scrolling).
* Meta description, Open Graph and Twitter tags (both languages), canonical link (when `PUBLIC_SITE_URL` is set),
  `robots.txt`, favicon, `lang` / `dir`, descriptive `alt` text.
* Images are WebP in responsive sizes with explicit dimensions (no layout shift); the hero image and the two Latin font
  files are preloaded; below-the-fold images are lazy-loaded.
* Bundle sizes (gzip): app ≈ 130 kB, 3D chunk ≈ 160 kB (lazy), CSS ≈ 8 kB; model 1.7 MB (lazy).

## 9. Hosting notes

The output is plain static files; any static host or web server will do. Upload the **contents** of `dist/`.

* Serve the site from the **root of a domain** (asset URLs start with `/`).
* HTTPS is required for the contact endpoint and recommended in general.
* Cache headers: `dist/assets/*` are content-hashed (cache for a year, `immutable`); fonts, images, `models/` and `draco/`
  can be cached for a week or more; `index.html` should be revalidated on every visit. (`npm run preview` shows the idea.)
  (If fonts are served with `Cache-Control: no-cache`, Chrome can print a harmless "preloaded but not used" warning on repeat
  visits; long-lived headers on `/fonts` avoid it.)
* MIME types: `.glb` → `model/gltf-binary`, `.wasm` → `application/wasm`, `.woff` → `font/woff`, `.webp` → `image/webp`.
* Enable gzip or Brotli for `.js`, `.css`, `.svg` and `.wasm` (the `.glb` is already compressed).

## 10. What was tested (and what was not)

All of this was run against the **production build** (`dist/`, served with `npm run preview`) by automated Chromium
(Playwright), in English and in Arabic wherever language matters. Desktop runs used 1440 × 900 with real classic
scrollbars; phone runs used 390 × 844 with touch emulation.

* **Hero and navigation** — the hero and its entrance; every menu link lands on its section and becomes the active link;
  the bar hides while scrolling down and returns on scrolling up; the mobile menu (focus trap, Esc, scroll lock, language
  switch inside it); the reserved scroll area directly under the hero.
* **Languages** — English ⇄ Arabic at five scroll positions: no reload, the same part of the same section stays on screen,
  the choice is saved, `<title>`, description and Open Graph tags follow, RTL and LTR with no horizontal overflow.
* **About story** — all five chapters in both languages: the model enters from the side, is never still, turns from
  chapter to chapter and crosses over between them, and the text appears and leaves. An automated sweep of 100 moments per
  run measured the chair's real outline against every visible line of text and against the edges of the screen: no
  overlap, the chair never leaves the screen, and text that has fully appeared is never cut off. Run at 1440 × 900,
  1366 × 657, 844 × 390, 667 × 375 and 390 × 844.
* **Model loading and fallbacks** — lazy loading of the model; reduced motion (and its opt-in button); no WebGL; WebGL
  context lost in the middle of the story.
* **Collections** — filters, the product dialog (focus, Esc, click outside, previous / next), the "Enquire" hand-off
  to the contact form.
* **Contact form** — validation, the honest "not connected" notice, success, server error, network failure, double-submit
  guard, Arabic, status text following a language switch (the endpoint was mocked inside the browser for these).
* **Footer** — wordmark, navigation, social links, copyright; the credit reads exactly "Crafted by 7mud", only "7mud" is a
  link, to the required address, opening in a new tab with `rel="noopener noreferrer"`, as the very last thing on the page.
* **Layout** — 16 window sizes from 320 × 568 to 2560 × 1300 (including laptop and landscape-phone sizes) in both languages:
  no horizontal overflow and nothing positioned outside the screen.
* **Quality** — no console errors or warnings, no "preloaded but not used" warnings, WCAG AA contrast for every visible
  piece of text on desktop and phone in both languages (measured from the rendered pixels, including text over the 3D
  scene), touch targets of at least 40 px on the phone, and a clean production build.

**Limits of that testing — please be aware:** the 3D scene was rendered with a *software* GL (SwiftShader), so smoothness on
real graphics hardware, on real phones and tablets, and in Safari and Firefox was **not** measured. Screen readers were
not run, and no Lighthouse or real-network timing was taken. The product images, contact details and social links are
placeholders. It is worth a pass on your own devices before launch.
